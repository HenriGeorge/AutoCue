Rekordbox → Serato

Prep your cues once in Rekordbox with AutoCue, then carry them — names, colors and comments included — into Serato DJ Pro with a single command.

Why Bridge to Serato

Rekordbox is a great preparation environment — AutoCue's phrase analysis, energy scores and comment enrichment all live there. But many controllers are Serato-native: a Pioneer DDJ-SX, for example, gives you every fader, jog and pad in Serato while Rekordbox won't even talk to it without a paid plan.

The Serato export ends that either/or. Your hot cues and enriched comments travel inside the music files themselves, so the library you prepped in Rekordbox arrives in Serato ready to play:

  • Prep in Rekordbox — AutoCue places and names cues, enriches comments.
  • Export once — autocue --library --serato mirrors everything into the files.
  • Mix in Serato — cues on the pads, comments in the browser, full hardware support.

How It Works

Serato stores hot cues in a tag inside each audio file (the reverse-engineered Serato Markers2 format). AutoCue writes that tag directly — no Serato-side import tool, no intermediate files.

The export is mirror-first: tracks that already have hot cues in your Rekordbox library export those exact cues — positions to the millisecond, names and colors included, manual tweaks preserved. Only tracks with no cues at all fall back to freshly generated ones.

Setup

  1. Install AutoCue with the Serato extra: pip install 'autocue[serato]' (adds the mutagen tag library).
  2. Quit both Rekordbox and Serato. Rekordbox locks its database while open; Serato caches file tags and the CLI refuses to run while it is open.
  3. That's it — no Serato-side configuration.

Running the Export

Preview first, then write:

  1. autocue --library --serato --dry-run — shows every track and cue that would be written; nothing is touched.
  2. autocue --library --serato — writes the tags. Expect a per-track line (mirroring 8 cue(s) from Rekordbox) and a final summary: written · skipped · comments updated · unsupported · missing.
  3. Open Serato and import your music. Fresh imports show the cues and comments immediately.

The Serato Cache Gotcha

Serato reads file tags on FIRST import only. If a track was already in Serato's library before you exported, Serato keeps showing its cached (cue-less) state — even after restarting. Fix: in Serato's Files panel, select the affected tracks and click Rescan ID3 Tags (or remove the tracks from the library and re-add them). Tracks imported after the export need nothing.

Re-runs & Safety

The export is designed to be run repeatedly — after every prep session:

  • Only changed tracks are rewritten. A per-track fingerprint (autocue_serato_state.json) makes re-runs incremental: files whose cues, loops and comment are unchanged since the last export are not touched at all. Anything replaced is backed up first.
  • Comments still update. A changed Rekordbox comment is written even when the cues are skipped, so enrichment stays in sync.
  • Everything replaced is backed up. Overwritten cue payloads and previous comments are appended to autocue_serato_backup.jsonl in the working directory.
  • Only metadata is touched. The audio stream is never rewritten.

Troubleshooting

  • Cues don't appear in Serato — the track was already in Serato's library. Files panel → Rescan ID3 Tags, or remove + re-add it. See the cache gotcha.
  • "Serato DJ appears to be running" — quit Serato fully (the CLI refuses on purpose; a running Serato can overwrite or ignore fresh tags).
  • "file not found" lines in the summary — those Rekordbox entries point at files that were moved or deleted. Fix them in Rekordbox (Relocate) and re-run.
  • WAV tracks show as unsupported — expected; Serato tag support for WAV isn't implemented. Convert to AIFF/FLAC if you need cues on those.
